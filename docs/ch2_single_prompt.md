# 第 2 章：一个提示词跑一圈

## 目标

用最直接的办法试一次：俯视图作首帧，一个提示词描述整圈，交给 MiniMax H3 生成 15 秒视频。看清楚它为什么不行，引出分镜。

## 演示

- 工作流：`workflows/ch2_single_prompt.json`（`LoadImage` 读 `fictional_track_v1.png`，H3 图生视频，768P，15 秒）。提示词是第 5、6 次尝试用的那一版。
- 历史结果：`media/ch2_single_prompt_01.mp4` 到 `_09.mp4`，输入图完全相同，只改提示词。

| 次序 | 提示词改动 | 结果 |
|---|---|---|
| 01 | 7 个元素 + “第一人称、逆时针、环境与俯视图一致” | 从地图飞进 3D 场景，第一视角嵌在地图的图例和海拔剖面中间 |
| 02 | 加“行进方向必须和输入图片一致” | 同上 |
| 03 | 加“从起始点开始” | 同上 |
| 04 | 重排元素列表，加“配音请使用中文” | 同上 |
| 05、06 | 说明起点在主看台附近、起点朝右是直道 | 两次提示词完全相同，结构几乎一样，只有细节不同 |
| 07 | 只拍“起终点直道到 T1 为止” | 画风变成卡通 |
| 08 | 再说明起终点线是黑白格子 | 仍是卡通 |
| 09 | 再加“路况和两侧环境与俯视图一致” | 全屏、写实的座舱视角，跑完了第一段直道 |

## 讲解要点

- **15 秒放不下一圈。** 前 6 次都想一次跑完，每次只跑了一小段，弯道顺序和方向也对不上。
- **模型把俯视图当成要动起来的画面。** 地图是首帧，所以视频总是从地图开始，地图上的图例和海拔剖面一直留在画面里。俯视图应该是剧本，不是输入。
- **“不可控”指什么。** 不是每次结果都不一样：5 号和 6 号输入相同，结果几乎一样，同样的输入重跑得不到不同的结果。难控制的是提示词：7、8 号只缩小了范围，画风就变了。所以要控制的是输入，不是靠多跑几次碰运气。
- **9 号是分镜的雏形。** 一次只拍一小段，并且明确要求和地图一致，结果马上可控。

## 结论

1. 一次只拍一小段：把一圈拆成镜头。
2. 首帧不该是俯视图，而应该是车手视角的画面：每个镜头的首尾都给一张关键帧。
